# Changelog

## 2026-10-21 — Исправление повреждённых systemd units при деплое

- Причина: на production в `.service` и `.timer` найдены строки `DRONE_SSH_PREV_COMMAND_EXIT_CODE`, вставленные `ssh-action` с `script_stop: true` внутрь heredoc. Мониторинг пока запускался, но конфигурация содержала посторонний shell-код и ошибки разбора.
- Unit-файлы вынесены в `ops/systemd/`; установщик проверяет их через `systemd-analyze verify`, копирует без shell-преобразований и проверяет активность timer. Ошибки запуска больше не игнорируются workflow.
- Добавлено объяснение причины и границ диагностики публичного DNS в README.
- Собственные проверки до коммита: `bash -n ops/install-systemd.sh`, `git diff --check`; оба candidate unit-файла проверены `systemd-analyze verify` на целевом production Linux с кодом 0 (единственное предупреждение относится к существующему стороннему `xray.service`). Старые units сохранены в закрытом резервном каталоге на сервере. Пользователь восстановление не подтверждал.
- Ограничение: этот фикс устраняет дефект деплоя мониторинга; недоступность авторитетных DNS REG.RU требует восстановления DNS или согласованного переноса полных зон.
